# i18n Overview

## App

- Supported app locales live in [`moontake.xcodeproj/project.pbxproj`](../moontake.xcodeproj/project.pbxproj) `knownRegions`: `en`, `zh-Hans`, `zh-Hant`, `zh-HK`, `ja`, `fr`, `de`, `uk`, `ru`, `es`, `es-419`, `pt-PT`, `pt-BR`.
- User-facing app copy belongs in [`moontake/Localizable.xcstrings`](../moontake/Localizable.xcstrings).
- Permission and bundle copy belongs in [`moontake/InfoPlist.xcstrings`](../moontake/InfoPlist.xcstrings).
- New strings should use stable namespaced keys. Avoid using rendered copy itself as the lookup key unless the string is intentionally temporary.
- Preferred key shape is `feature.scope.role`, with `lower_snake_case` for multiword segments, for example `camera.shutter_speed.value`, `settings.white_balance.title`, and `membership.learn_more`.
- Interpolated copy should go through format keys in the string catalog instead of string concatenation in Swift. This keeps word order adjustable per locale.
- Locale-specific behavior must resolve from the app’s selected localization, not from translated display text.

## Website

- The website is a static multilingual site under [`website`](../website).
- Default English page: [`website/index.html`](../website/index.html).
- Locale pages currently exist for `ar`, `de`, `es`, `fr`, `it`, `ja`, `ko`, `pt`, `ru`, `tr`, `uk`, `zh`, and `zh-hant`.
- Shared assets live in [`website/assets/css/styles.css`](../website/assets/css/styles.css) and [`website/assets/js/site.js`](../website/assets/js/site.js).
- Website translations are maintained as separate HTML files today, so copy changes need to be applied page by page.

## Practical Rule

- If a copy change affects both product and marketing site, update the app string catalog and the matching website locale pages in the same pass.
